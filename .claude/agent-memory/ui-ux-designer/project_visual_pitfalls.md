- Not hash-stable (checked 2026-11-02 with two runs on the same build): `data-display-logviewer--{default,terminal,with-ansi-colors,errors-only,flex-parent,large-buffer}`, because their stories use `new Date()` timestamps. `--streaming` was stable, and so are `--app-registers-no-icons` (fixed dates) and all NC stories (034 re-run 120/120); `components-chat--with-diff-viewer` is not stable (clock times). Review them by `--measure`, and ask for fixed timestamps in new log-viewer stories.
- Stable: search-input, the icon stories (except inline-set and icon-constants when the set changes), code-block, copy-field, kanban, treeview, filter-bar, input with-icon, empty-state no-results, list with-disabled.
- `layout-app-shell--today-loading` at 360 **dark** is timing-sensitive: a `--measure` that waits (2 rAF) or injects a `<style>` shifts the frame, so it differs from a shot without one (all shifted shots are byte-identical; light and the other widths are stable; 032). To prove a change hash-neutral, re-shoot with a wait-only measure (no CSS) and `cmp` both: equal bytes = timing, not the change.
- `layout-app-shell--full-height-nav` is not hash-stable (045, 3.27.2–3.28): 4–6 of its 10 shots (360–1920 L/D) differ per run, a different set each time (sidenav icon pixels at x 17–21 / 34–38). Exclude it from "N/N identical" claims or re-run it once to show the set moves.
- `layout-app-shell--toasts-in-the-shell` dark shots flip by hash between runs (053: 360/1024 D in one run, 1280 D in the next, 0 in r1) with identical stack geometry: check the rects, not the hash.
- `navigation-sidenav--drawer-mode` 1280 **dark** (050 r1): baseline differs from 3 later re-shoots that are byte-equal to each other, with an unchanged DOM (close button auto-focused at open). Also flaky: sidenav sidebar-first-layout 1024/1280, prominent-brand 1024/1280 L, collapsed-rail-badges 360. Shots taken after a `.focus()`/`.blur()` pass in `--measure` differ in bytes from at-rest shots (floating bar, sidenav at 1024+) with no computed-style change: keep focus passes out of compare runs.
- 051: also flaky `navigation-sidenav--collapsed-icon-rail` 360 D; `--docked` 360 D differed only with a 13 kB injected `<style>`. `collapsed-rail-badges` at 360 renders two overlapping drawers (the light one on top), so the dark rail is invisible there.
- `charts-scatter-plot--compact` uses `Math.random()` data: it differs on every run (057), so a palette-change compare must exclude it.
- 065 r1: `data-display-table--{full-featured,with-filtering,with-pagination}` 1024/1280 differ per run (mine ≠ developer's ≠ baseline); `data-display-area-map--all-bands` too. Exclude from "identical" claims.
- Icon size grids (label + 16/20/24/32/40 px) overflow 328 px at 360 with a 24 px column gap; use an 8 px gap and labels of at most 18 monospace characters.
- 057 design: `opacity` → an alpha colour is the same composite but changes every hash (glyph anti-aliasing), so keep the prototype shots as the expected build (`tmp/story-shots/057/proto-*`). Add-class-then-read in one `--measure` task gave stale layout: wait 300 ms. A transparent non-focusable overlay makes axe pass the cells beneath as `obscured`. A leading space inside an inline-flex badge collapses; a `font-size: 0` span is a 0 px separator that axe still reads. `--compare` prints every shot: grep `different`.
- 058 r1: an injected-CSS prototype on the old build differs from the real build only at the **rounded ends of pills** (lc-badge, inverse buttons) inside a slot (≤ 15 px per end, Δ ≤ 69 at 360, Δ ≤ 2 in FC), although their CSS is unchanged. Re-injecting the rule or forcing a repaint on the build doesn't reproduce it. Accept it after measuring colours and geometry, and make the build shots the new reference. Don't promise "build = prototype by hash" for stories with pills.
- 067 r1 (3.47): re-baseline `navigation-sidenav--themed-rail-badges` 360 D (icon edges x 34–37, Δ ≤ 36) and `--area-rail-german` 360 D (Δ ≤ 12), AA-only, same DOM. Sidenav sidebar-first-layout 1024/1280 L, prominent-brand 360 L, sidebar-first-collapsed 1024/1280 L differ by one Δ 1 pixel at (W−1, 6): noise. 067 r2: `--axe` on sidenav stories with a hard-coded `#f9fafb` content box (*With Groups And Actions* etc., 7 stories) fails `color-contrast` on the h3 in dark (1.04), pre-existing, queued as 067 F-9 — not caused by a sidenav change. 068 r1: datepicker *Time (DE)* (play opens the list) drew its list at 64/71 over the field when run after *Time* in one story-shots run; alone it is 16/87 → probe overlay stories singly before calling it a bug. A developer's `--compare` taken before their last story edits (story file mtime > shot mtime) must be re-run for those files.
- 064 r1 (3.44 baseline `tmp/story-shots/064/baseline`): `navigation-sidenav--text-brand-drawer-german` 1280 D differs deterministically after 3.44 (21 px of corner anti-aliasing on the brand tile r 10 and the current item r 12, fills and rects equal): re-baseline it. Sidenav flakes seen across 5 runs: collapsed-vs-expanded 360 L/D, drawer-mode 360/1280 D, sidebar-first-layout 360/1280, sidebar-first-collapsed 360 L, prominent-brand 360 L, collapsed-rail-badges 360, themed-rail-badges 360/1280 (flips); app-shell wide-page 360 D once. After `lc-tabs` became a scroll container (3.44) every tabs shot differs by AA (Δ1–2): re-baseline tabs and page-header *Full Example* / *With Body Content*.

- 069 r1 vs the 069 baselines: `navigation-sidenav--action-items` 1280 L/D differs (busy spinner frame, Δ ≤ 2) and `--themed-rail-badges` 1280 D (rail icon edges x 34–37, Δ ≤ 36), byte-equal in the dev's and the review run: baseline outliers, not badge changes. Palette ×11 the dev saw were identical in r1.

**Why:** a hash diff on an unstable story wastes a shot opening in review.
**How to apply:** do a quick stability re-run when capturing baselines (`--compare` against the fresh baseline).
