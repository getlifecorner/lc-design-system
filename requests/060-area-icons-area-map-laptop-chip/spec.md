# Spec 060: Area icons, hero area map, laptop device frame, lc-chip wrap and on-band palette

- **Status:** ready
- **Type:** bundle of 5 items: icons (extension of the inline set), new pattern/component (area map), extension of `lc-device-frame`, extension of `lc-chip` (two items)
- **Affected:** `lib/icons/icons.data.ts` (generated by `scripts/generate-icon-names.mjs`), `lib/hero` + `lib/chip` + `lib/badge` (reference only) + a new area-map unit, `lib/device-frame`, `lib/chip`, `_theme-light.scss` / `_theme-dark.scss` (on-band chip palette, next to the badge one), both READMEs, CHANGELOG, MCP manifest (picks up inputs and stories)
- **Semver impact:** minor. All additions are optional and default to today's rendering. (Item G-HV4 changes how chips look inside `lc-hero`, see AC-14: allowed only because chips there are unreadable or unstyled today; the designer checks the kit's own stories for chips in a hero first.)

## Need

Page: the life-os website home ("home vision", `website-home-vision.md` sections 3, 7). Requester: life-os. All five items are listed as gaps with the owner decision "kit first" (2026-11-11).

| Item | Problem today | Interim in life-os |
|---|---|---|
| G-HV1 (blocking) | the inline set has no glyph for shopping, goals, health, people who matter | page waits for the release |
| G-HV2 | an area map on a hero band (status groups, lines into one translucent layer bar, quieter groups below a divider) has to be built as page CSS; the lines must work in prerendered HTML with zero JS | page-level layout in `page-level.scss`, labelled |
| G-SS1 (extended) | `lc-device-frame` (3.39) draws only a phone | `lc-card` outlined, radius lg |
| G-HV3 | `lc-chip` never wraps: at 320 px and 200 % text a long label overflows (WCAG 1.4.10). Widest chip today 254 of 272 px (DE "Gesundheit, Fitness, Ernährung") | chips fit 320 px at 100 % |
| G-HV4 | chips on a hero band have no on-band palette; badges have had one since 3.37 | page-level `--lc-chip-bg/-fg/-border` hooks, labelled |

## What the kit has today

- Icons: `ICON_*` constants in `icons.data.ts` (Tabler outline: 24 viewBox, stroke 2, `currentColor`, e.g. `ICON_USERS`). None of the four exists (grep `ICON_(SHOPPING_BAG|TARGET|HEART|GIFT)`: no match; `ICON_HEART` does not exist in any variant).
- `lc-badge` `wrap` (3.11): `--wrap` class, `max-width: 100%`, `white-space: normal`, centred, line-height 1.25, `overflow-wrap: anywhere`, per-size heights and radii. Pattern to follow for chips.
- Badge light palette in a hero in both themes (3.37, `_theme-light.scss`, comment in `hero.component.scss` ~l.401): 4.85:1 or more on all nine bands.
- `lc-chip`: variants and `--lc-chip-bg/-fg/-border/-gap` hooks, sizes, `icon`; `white-space` is not wrappable; no hero handling (grep `hero` in `chip/`: none).
- `lc-device-frame`: `device` input typed `'phone'` only, "more may follow"; hooks `--lc-device-frame-*`.
- `lc-hero`: `[hero-media]` slot, `--lc-hero-media-width`. No area-map pattern anywhere.

## Scope

- In: the five items below, each with stories at the widths named.
- Not in: chip outline variant, dashed border, a chip size below `sm` (G-HV5 in the concept; not filed here); any change to the bands, `lc-card` or `lc-character`; the page itself.

## Constraints

- Peer range `^21.0.0 || ^22.0.0` unchanged; no new runtime dependency; anchor positioning only as progressive enhancement (Chromium 125+, Safari 26+), fallback AC-7.
- No raw colours except where a band palette needs them; prefer tokens.
- Compat check (AOT, strictTemplates, prerender) on Angular 21 and 22 must pass.

## Assumptions

- Assumption: the folded BACKLOG rows: none exist for icons, chip, hero area map or device-frame (grep returned nothing).
- Assumption: the area map is a new unit in the kit, not a docs-only recipe, because the requester asked for a pattern and CSS-only anchors need shipped styles; the designer may choose a component or a hero-media recipe as long as AC-4 to AC-10 hold.
- Assumption: `lc-badge` hero palette values from `_theme-light.scss` are the reference for chip on-band tints.
- Assumption: G-HV4 is automatic inside `lc-hero` (like badges), not an opt-in input; if the designer finds a conflict with existing chips in heroes, an opt-in is acceptable provided the default stays unchanged.
- Assumption: the concept's colour values (section 3.3, 3.1 `--hv-under`) are the requester's target, not a requirement to match exactly; AC-14 decides.
